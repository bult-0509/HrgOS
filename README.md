# HRG 国庆特别综艺 Web App

面向杭州西湖线下活动的本机运行 Web App 首版。当前包含玩家端、工作人员端、PWA 基础能力和可替换棋盘接口。

## 能力卡和正式比赛后端

新增接通后端的比赛界面：开发访问 `/?live=cards`；隔离体验 `/?live=cards&training=1`；测试页新增“一键测试 24 张能力卡”。24张卡包含库存、确认/接收、暂停冻结计时、证据上传、工作人员结算、真实历史回返、临时排名/追逐定位、半分奖励和任务交换。全体累计每完成10个审核通过的普通任务，会向每队各发一张随机能力卡，同队成员共享库存。

开赛后每累计30分钟，后端自动向每队独立随机发一张能力卡，允许重复；暂停冻结、结束停止，重启补发且不重复。与十任务发卡独立累计。新卡以奖励浮层展示：翻面、光晕、粒子及确认后飞入牌库；同队各成员独立展示、共享库存。

`npm run test:abilities:local` 当前26项通过（24张卡、全体十任务发卡、半小时发卡）、0失败、1项实机/异地待验收。完整规则见 [能力卡说明](docs/ability-cards.md)。正式赛局独立持久化，测试时钟/清理不能操作正式比赛；完整前端、API和PostgreSQL部署见 [部署说明](deploy/README.md)。新比赛默认载入125项正式任务及800/600/400/250/100完赛奖励；工作人员核对规则和备用任务池后开始。旧READY赛局可载入预设，已开赛赛局保持原价。

下面的原型介绍描述旧版 `DemoApp`。新版界面已接通卡牌、任务/区域审核与前台定位；自创事件、通用文本收件、最低队伍特殊挑战和系统 Web Push仍待实现。

## 本地运行

```bash
npm install
npm run dev
```

打开 `http://127.0.0.1:3000/`。登录页可切换玩家账号与工作人员账号；当前为交互原型，账号和密码输入框默认为空。

## 登录展示限制

- 已废除原默认凭据和旧编号玩家账号。现有 4 个工作人员账号（`hrg-staff-01` 至 `hrg-staff-04`）和 15 个玩家账号，玩家账号采用昵称对应的字母数字变体。
- 每个账号使用独立随机密码，身份固定；玩家账号不能登录工作人员端，工作人员账号不能登录玩家端。
- 本机分发清单：`local-private/活动账号清单-20261007.csv`，玩家分组和凭据另保存在项目根目录的 `失序重奏志愿分组与账号表-20261007.xlsx`。这两份文件均不提交 Git，也不作为网页资源提供。
- 前端账号配置仅保存加盐 SHA-256 校验值，不保存明文密码。此处仍是演示页面的登录门槛，不等于后端鉴权。
- 其余账号密码提交后只显示“请等待游戏开始”和配套背景图，不展示任务、道具、排名或工作人员数据。
- 登录页不预填默认凭据；`?preview=player` 和 `?preview=staff` 不再绕过登录。
- 原有演示界面及数据按需载入。这是前端展示限制，正式的数据保密和鉴权仍需后端实现。
- 玩家结合报名志愿和常玩游戏分为 Phigros、Arcaea、范式起源、maimai、全能五队，人数分别为 4、2、2、4、3，含补录的 Zénith Céleste。12 人满足第一志愿，ForzxOL、椿烨按第二志愿分配，RS-圆愿按用户补充许可进入全能。半月荷保留 Phigros，灵均子美、Fidrop、萤川白保留同队。登录后按绑定队伍显示队名、分数和区域。
- 分发表凭据已与 `src/data/loginAccounts.ts` 对齐，服务器重新构建并部署本次代码后生效。修改表格不会自动修改网站账号或队伍，需要同步配置并重新部署。
- 当前比赛数据仍为演示数据，尚未接入多人共享的后端状态及持久化。

## 已实现范围

- 玩家端：区域进度、任务图库、图片单张提交、卡牌使用、消息中心、事件与排名快照展示。
- 区域按参赛队独立推进，玩家不能自由切区。工作人员通过本队下一地区入口审核后，五张Bingo各自复用的19张图统一更新；固定五套各25项任务、各6个直接任务、分数和完成状态不重置。区域进度只读，普通任务审核和入口提交本身都不换区。
- 工作人员端：总览、FIFO 审核队列、队长位置、离线/完赛标识、现场完赛确认与操作留痕展示。
- 技术基础：React + TypeScript + Vite、PWA manifest/service worker、响应式布局、本地阿里妈妈方圆体。
- 解耦接口：棋盘通过 `BoardAdapter` 提供任务状态与选择事件，后续视觉方案可直接替换。

## 一键规则联调和异地数据库

```bash
npm run test:lab
```

按终端提示打开测试页面，从 `local-private/rules-test-key.txt` 复制密钥，点击“一键执行规则测试”。也可双击 `启动规则测试.bat`。默认运行本机 PostgreSQL WASM 验证库；异地环境使用 PostgreSQL 17、API 和 HTTPS 网关，部署脚本及操作步骤见 [规则联调说明](docs/rule-testing.md)。

测试页与命令行共用 31 项自动检查，另列 4 项待实机/正式环境验收。可以选择真实 GPS 和相机检查，并导出不含账号密码、媒体和经纬度的报告。

新增“专项功能验收”用于检查事件创作、文本收件、最低队伍挑战与区域完成发卡。当前仍有未实现项，见 [功能专项验收结果](docs/feature-readiness.md)。

后端支持正式与隔离测试赛局，包含服务端鉴权、事务、媒体访问控制、定位与WebSocket同步。正式玩家/工作人员界面已接入服务端；影像原件当前存于数据库，生产对象存储和真实Web Push仍需后续实现。异地部署不能替代实机GPS与现场行为验收。

演示页面的区域审核由 `src/domain/regionProgress.ts` 的 reducer 演示，PlayerApp 只读接收 `approvedRegionId`。正式比赛界面从服务器取得本队已批准的 `regionId`，提交到达证据不会立即换区，工作人员审核通过后才统一更新 19 张图。独立美术预览只显示区域 02 快照，不提供区域切换。

棋盘美术与正式提交入口的本机浏览器验证：`node scripts/verify-bingo-integration.cjs`，覆盖五队、两套页面、五种屏幕尺寸、图层顺序、装饰与点击区域、清晰图弹窗、提交失败保留草稿及审核换区。该验证拦截 API，不会操作真实比赛；截图及报告位于 `artifacts/bingo-integration-20261007/`（不提交仓库）。

正式任务配置接受125项全局唯一任务，每项`boardId`为`team-1`至`team-5`，每个主题25项；`boardId`只决定分类，不限制提交队伍。服务端根据会话记录提交队伍，不信任请求中传入的队伍身份。可省略整张棋盘的`sharedSlot`采用既定19+6布局，或完整指定P01–P19和D01–D06。旧25项配置继续显示其真实单棋盘，不重复生成125项。演示与正式页使用同一125项分值来源；每主题4000、中心极难400，每队每区最多5项普通计分任务。Random3达标＋50、两项Arcaea逐次失败−50、完赛并列均独立记账，工作人员可在界面核验。
