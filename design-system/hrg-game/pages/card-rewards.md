# 能力卡展示与动效

适用入口：玩家预览、正式能力卡页、工作人员发卡预览。使用 ui-ux-pro-max 的动效与弹窗检查规则。手牌、详情、奖励、出牌使用同一个卡面组件，避免重复皮肤相互覆盖。

## 原作参考

参考一代《杀戮尖塔》开发者的 [Cards of the Spire](https://www.indiedb.com/games/slay-the-spire/news/cards-of-the-spire) 演示：卡牌从集中状态展开，选中卡牌抬起、放大并置顶，确认后向牌库缩小飞入。本活动随机发放一张卡，不增加三选一机制。短暂翻面是网页版本的入场设计，并非逐帧复刻原作。卡框、卡背和分类图形均在本项目绘制，原作图片不进入构建。

## 视觉与层级

保留阿里妈妈方圆体。金属边框、分类插图、纸面规则区组成唯一卡面。情报为青色、增益为黄绿、干扰为粉紫；颜色只用于分类，不代表服务器权限或费用。正式卡与本地预览均显示功能卡原编号；仅不带编号的历史卡使用次数角标。

手牌扇形重叠，抬牌在外层按钮，发牌入场在内层，两个 transform 不互相覆盖。只有支持悬停的精确指针触发悬停抬牌；键盘焦点同样置顶，触屏点击读详情并横向滚动。长规则在详情和奖励卡面内可滚动，保持 16 px，不删改规则正文。

所有阻塞弹窗使用 portal 与原生 dialog 的顶层，背景不可点击、键盘焦点限制在弹窗内。滚动锁引用计数，关闭弹窗后恢复之前的焦点与滚动。右下角牌库锚点使用同一个组件；奖励层中仅绘制与实际锚点对齐的视觉落点，不重复放置可交互按钮。

## 接收、出牌与异常

接收按入场 → 阅读 → 服务器确认 → 飞入牌库进行。入场 480 ms，翻面 480 ms、延迟 140 ms，680 ms 后稳定阅读。入场期间也可直接确认，不强迫等待。点击后显示“确认中”，禁用重复操作；失败保留卡面与重试。确认成功后用 560 ms 曲线路径收纳，视觉动画取消或超时不回滚服务器确认。

Escape 在入场阶段跳过动效，在阅读阶段等同“稍后查看”；确认与飞行阶段不重复提交。“稍后查看”不写展示确认，同次会话暂不重复弹出，下次登录仍可看到。出牌只在服务器操作成功后播放 720 ms 的抬起、送出反馈，和接收动画互不叠加。动画、计时器、滚动锁在卸载时清理。

prefers-reduced-motion 跳过翻转、光晕和飞行，直接展示并确认。偏好在动画中变化时也能中止动效。小屏和横屏采用独立布局，确认按钮至少 48 px，底部预留安全区与牌库空间。

## 数据边界

任务题面和数量不由美术组件生成：每张 Bingo 使用项目既有 25 个格位，题面、分值和图片规则不改。能力卡标题、规则直接读取服务器 abilityCatalog；前端不创造新卡规则，不修改后端 target、发卡、扣卡或计分逻辑。

真实收下仅调用 ability_reveal 更新本账号的 revealedBy，不消耗共享库存。同队成员各看一次；补到的多张卡依次展示，已使用、历史无标记和缺少定义的卡不阻塞队列。新奖励等任务、出牌或消息弹窗结束后展示。

本地玩家预览的卡池选择器可逐张展示项目现有功能卡，来源与正式后端共用 src/data/abilityCatalog.json，名称见 docs/tactical-card-names.md。前三张真实卡仅作本地初始手牌；完整卡池不是已持有库存。选择“收卡动效预览”不增减库存，初始手牌不伪装为新奖励，出牌明确标记为本地模拟。工作人员预览也不发卡或发送展示确认。

实现：src/cards/、src/components/overlay.ts、src/ability/CardRewards.tsx、src/ability/CardInventory.tsx。浏览器验收脚本：scripts/verify-card-motion.cjs；测试库存与请求仅在内存中，不修改真实比赛。

本机 3000 端口开发服务运行时，执行 npm run test:cards:ui。覆盖 78 项浏览器检查，包括窄屏与横屏、提前收卡、排队、确认失败、重复点击、飞行取消、动态偏好变更、焦点恢复、正式出牌入口，以及完整功能卡池逐张核对名称和规则。截图保存于 artifacts/card-motion/。
