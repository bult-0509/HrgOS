# 图寻复刻与任务解锁

图寻是复刻参考照片所在地点与拍摄角度，由工作人员人工核验，不是提交地名或仅到达区域。

- P01–P19：格子公开编号、分数、难度颜色与状态。点开仅显示清晰参考图和复刻照提交入口，任务标题、要求和额外分值规则保持隐藏。
- 本队复刻照审核通过后，五张Bingo中共用该照片的五个任务同时解锁，仍须点格子查看。D01–D06不经过图寻。
- 图寻提交进入现有FIFO队列。提交、等待审核、打回不解锁；打回后可重新提交。通过不计普通任务分、不占每区任务名额、不改变区域，也不触发任务完成发卡。
- 权威记录以参赛队伍、区域、图片编号为键。切换棋盘不换身份、区域或图寻进度；进入新区域后，19张新图重新图寻，历史记录保留。旧地区的迟到审批只记录旧地区，不解锁新图片。
- 服务端`stateView`只返回未解锁任务的公开字段；`submit kind=task`拒绝未完成图寻的P格任务。`submit kind=photo`使用`photoSlot`，不接受请求体中的队伍身份；原件仅本队与工作人员可访问。
- 图寻与任务分别上传，图片审核通过不会把复刻照自动当成任务证据。工作人员界面同时提供参考图和提交照片，按地点、角度核验。

绿/黄/红/紫对应易/中/难/极难，带难度文字和无障碍标签。已解锁的任务正文采用更大字号、高对比独立内容块；删除玩家端“拍摄要求”说明块。

验证：`node --test server/photoFinds.check.mjs`及`node scripts/verify-photo-find-gate.cjs`。浏览器脚本只使用内存赛局和拦截请求，不操作真实比赛，覆盖两套页面、四种屏幕、未解锁/待审/已通过、共享五项解锁、直接任务和上传失败草稿。截图位于`artifacts/photo-find-gate-20261007/`。

演示页仍只记录文件名，不上传原照片，不冒充正式审核。正式比赛需运行更新后的后端。

正式发布使用`VITE_ENABLE_LIVE_GAME=true`构建，此时不包含有完整题面的本地演示分包。工作人员在配置页点击“载入后台当前配置”取得已鉴权的任务表；题面不再内置于正式页面的配置模板。Vite开发服务和本地演示不是隐藏题面的安全发布方式，不应直接开放给参赛者。
