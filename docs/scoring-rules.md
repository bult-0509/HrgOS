# HRG 125项任务与积分规则

正式规则版本为 `hrg-20261007-v1`。前端与后端共同读取 [scoringRules.json](../src/data/scoringRules.json)，逐项任务、基础分、格位、难度和题面奖惩在同一份数据中维护。完整表格见 [125项积分与Bingo对应表](../outputs/task-integration-20261006/HRG125项任务_正式积分与Bingo对应.xlsx)。历史海报中的“每区最多完成5项”在本版统一为“每区最多领取5项普通任务基础奖励”；审核完成计数与积分归属分别计算，以下口径为准。

## 任务与图片

Phigros、Arcaea、范式起源、maimai、通用各25项，共125个全局唯一任务ID。五个棋盘是共享任务分类；所有队伍可以跨棋盘完成任务，得分、区域进度、定位和登录身份始终属于实际提交队伍。

每张5×5棋盘含19个图寻格P01–P19与6个直接任务格D01–D06。每主题的极难任务为中心D03，固定400分。玩家格子难度颜色：易绿色、中黄色、难红色、极难紫色，向内轻渐变，不显示编号和难度徽标；详情与读屏标签保留难度。普通任务审核完成后格子泛红，不代表重新计分或图寻解锁。直接任务不需要图寻图片，但完成审核仍需现场证据。

图寻格按本队经工作人员审核通过的区域换图：西湖文化广场→武林广场→龙翔桥。三个区域各19张独立图片，共57张。五个主题复用同编号图片；同图号不表示同一个任务。换区不会重置任务归属或重新奖励。格子公开编号、难度及基础分；P格题面须本队复刻照片的地点与角度并通过审核后才能查看，同一图片一次审核解锁五个对应任务。D格直接查看；图寻本身不额外计分、不占普通任务名额。详见 [图寻与任务解锁](photo-find-rules.md)。

## 计分与归属

总积分＝普通任务基础分＋题面额外奖励−题面失败扣分＋事件与能力卡净变动＋完赛奖励。负分允许存在；能力卡的半分奖励和并列完赛平均分保留小数，并列均值及总分按服务端统一保留至小数点后6位。

任务提交按服务器接收顺序进入FIFO审核。相同任务ID只由最早有效完成且符合区域计分上限的队伍获得一次基础分；打回不占任务归属。每队每区域最多领取5项普通任务基础奖励，三个区域最多15项。其他队伍后来完成或上限已满时可审核为完成，但无基础分、无达标额外奖励。全体十任务发卡仍按“队伍＋任务ID”的首次审核完成去重，包含审核通过但未计分的完成，详细见 [能力卡规则](ability-cards.md)。

五个主题各有4000分基础分池，总池20000。4000是主题预算，不是参赛队伍的得分上限。跨全部125项选15个最高基础分，理论合计4300；最低15项合计1200。这是忽略抢占、耗时、路线和能力卡限制的组合边界，不是预计成绩或胜率。每主题内部的高低15项统计不能用作跨棋盘队伍的上限。

PHI21“Random3”首次计分完成时，工作人员核验课题成绩≥2990000，额外＋50；未填成绩或未达标只发基础分。额外奖励独立记账，不占4000分主题预算，也不通过其他队伍重复领取。

ARC04和ARC11题面实际失败每次−50。工作人员可以在任务审核时填写本次尚未入账的失败次数，或从“记录题面失败扣分”独立登记，须填写核验依据。独立记录有唯一尝试编号，同一记录重试不会重复扣分。已独立登记的失败不得再次填入审核；真正新增失败应使用新记录。证据模糊、上传错误或普通审核打回默认不扣分，题面真实失败与基础分归属分开结算。

ARC01的换行“-100000”和ARC05的“11/11 /12”保留原题面，不据此自动产生积分扣罚；工作人员须在现场明确完成门槛。相同现场行为不能用同一证据重复申领两条任务，例如ARC23与ALL22须各有一次独立卸载行为，审核时核对证据。

PHI24提供“将本人的昵称改为零零五”按钮，仅修改当前玩家；之后每项任务开始前“溜一遍说的道理”仍由工作人员现场核验，改名本身不会自动发任务分。

## 完赛与最终排名

| 现场确认完赛名次 | 奖励 | 与下一名的差额 |
| --- | ---: | ---: |
| 1 | 800 | 200 |
| 2 | 600 | 200 |
| 3 | 400 | 150 |
| 4 | 250 | 150 |
| 5 | 100 | — |

工作人员须确认龙翔桥区域已通过审核、本队无待审任务证据、涉及本队的待处理能力效果已结清，再确认完赛。名次由现场有效完赛确认顺序决定；确认依据必填。单次多选队伍只用于确实同时抵达、同批确认的并列：平分所占名次奖励，下一个名次跳位。例如第2、3名并列各500分，下一队为第4名250分。相同服务器毫秒的不同操作不自动并列。未完赛不发奖励；幂等重试不重复发奖。

相邻完赛差150–200、首末差700，使速度有明显作用，同时任务或事件分差能反超。例如甲任务2200、第1名，总3000；乙任务2500、第2名，总3100。五个极难任务各400，单个不会超过首末名次差。能力卡既有转移100（双方分差变化200）、失败−100、每缺一次−25、总分交换等机制保留；总分交换或大量罚分可能主导个别赛局，不能保证名次在所有赛局中影响比例相同。

最终排名依次比较：总积分降序→普通TASK基础分降序→现场确认完赛时间升序；三者相同并列。完赛名次不是直接的最终胜负名次。

## 定价与维护

逐项权重＝技能基准＋时间附加＋协作附加＋不确定性附加＋图寻附加。技能基准易80、中130、难190、极难350；估计单次时间≤2/5/10/15/超过15分钟分别附加0/10/30/50/70；协作0/10/20/30，不确定性0/10/20，P格图寻附加20，D格0。耗时是策划估计，不包含寻图、排队或重试，仍需现场复核。

极难固定400，其余24项按每主题系数归一为3600，先按10分向下取整，再按余数从大到小补10，同余数按任务序号。图寻附加已计入基础分，不另发20；题面奖惩不乘系数。任务重演沿用实际普通TASK基础账本的50%，不含额外奖励、事件净分或完赛分，不重新占普通计分格。

策划原始依据在 `outputs/task-integration-20261006/score-inputs.json` 和 `bingo-score-plan.json`；运行 `npm run sync:scoring` 同步到正式数据后，必须验证125项唯一ID、五主题各4000、完整19+6格位与五个极难中心格。修改策划因子后须重新计算取整补分与映射，不能仅改系数后假设仍合计4000。

新建正式比赛默认载入本版本，可在READY状态通过“载入正式125项积分规则”更新已有未开赛比赛；更改会留配置历史与审计。已开赛/暂停/结束的赛局不自动改价，历史账本不会按新价格回算。自定义赛局可显式用 `preset: "custom"` 创建空配置，并在开赛前配置。统一旧 `finishPoints` 仅兼容没有名次奖励表的旧赛局，正式版本拒绝修改会被忽略的统一完赛分。
